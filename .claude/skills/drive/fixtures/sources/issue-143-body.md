## What to build

"The later Assessment" has one order in the code: the write-journal position first, then `(recorded_at, id)`, as `decisions.py` computes it today. `status` (whether a Decision still applies), `assess` (which earlier Assessment its `rescoring` names) and `report` (the order in which the page lists Assessments) all use it.

How each orders Assessments at `c77b9a6`:

- `core/decisions.py:78-85` (`_journal_positions`): an Assessment's position is that of the first entry of the write journal whose `written` list names it, from 1; an Assessment that no entry names is absent, so position 0. `core/decisions.py:91-92` (`order`, inside `_reasons`): the key is `(position, recorded_at, assessment_id)`, with `recorded_at` read as `assessment.get("recorded_at", "")`. `core/decisions.py:106` compares with it and `:109` takes `max(later, key=order)`.
- `core/rescoring.py:56`: each candidate earlier Assessment is kept as `(recorded_at, assessment_id, record, causes)`, with `earlier.get("recorded_at", "")`; `core/rescoring.py:59`: `max(candidates, key=lambda c: c[:2])`, so the latest by `(recorded_at, id)`, with no journal position.
- `report/gather.py:136` (`_load_regression`, a regression Study): `assessments.sort(key=lambda a: (a["record"].get("recorded_at", ""), a["record"]["assessment_id"]))`, so `(recorded_at, id)`, with no journal position. `report/gather.py:109-112` sends an agentic Study to `report/gather_agent.py`, whose `load` sorts the same way at `report/gather_agent.py:71`.

So when the journal order and `recorded_at` disagree (a clock set back between two `assess` commands), `assessment_superseded` and `rescoring.earlier_assessment_id` can name different Assessments, and the page lists them in a third order.

No model is called. The rule of what makes an Assessment later (the same Observation set and the same Scorer id for `assessment_superseded`; the three causes for `rescoring`) stays as it is: only the order changes.
