# Two HTML books: an English handbook here, a French learning book elsewhere

Status: accepted

Every change is explained in readable HTML, not only in code and ADRs. Because everything committed here is in English, the material serves two readers through two books. The **handbook** (`docs/handbook/`, English only) is a reference for someone taking over the project: what each part does, how to run it, its limits, and which ADR explains it; it is updated in the same pull request as any behaviour it describes. The **learning book** lives in `chadlis/hypotrail-learning` (French by default, with an English switch): a guided path from selected competencies to their implementation in Hypotrail and the reason for that choice. A chapter may connect several delivery slices and is written or updated when it supports a requested learning session. A fresh-context writer is preferred, using pinned code, notes, the glossary and ADRs. Chapter generation never blocks a learning session or product delivery.

## Consequences

- Each book has one source file per chapter, assembled by a standard-library script into one self-contained HTML file. The product handbook follows current behaviour and is updated in the relevant pull request. Each learning chapter displays its code revision and verification date, is checked before reuse, and is updated when needed for a requested session. An unchecked chapter is not presented as describing current main. Design history stays in ADRs, while learning records remain dated observations.
- The learning book never restates a decision: it links to code at a pinned commit and to the ADR. The handbook never teaches concepts.
- Every HTML page uses the cosmic-couture charter in light mode by default; step-by-step mechanisms may be animated with the mechanism-explainer approach.
- Study reports generated by the software are English only in the first milestone.

## Amendment — 2026-11-04

The learning book is organised around selected transferable competencies, not a mandatory chapter per pull request. Existing chapters and links remain valid with their stated revision. A completed lesson is not a product approval or evidence of transfer to another task. Anki provides initial calibration, supplemented by targeted application and observed performance. The two learning stages and deferred recall are defined in the paired drive and hypotrail-study skills. Product documentation continues to cover every behaviour change.

Delivery slices keep concise notes and links. They do not automatically create learning issues. A learning issue is created or reused only when a competency objective is selected during a requested learning session, or explicitly requested by the owner. It can cover several slices and sessions. The tutor manages the objective, while drive enriches already linked objectives without creating one for each delivery. Existing learning issues remain compatible and are not bulk-migrated.
