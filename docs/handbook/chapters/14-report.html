report renders one HTML page for a Study of either Track, the temporal regression Track (Bike) or the tool-using agent Track (Chinook), from the Study's records: the Attempts, Observation sets, Assessments, Comparisons, the freeze record and the Exposure journal. The page of a Bike Study also draws the data profile that profile reads (chapter 02), which the command hands it. The page holds its text, styles and tables inline, loads nothing, has no script and computes nothing when it is opened. A page that shows public_check Items is an Exposure and is recorded as one.

The command

python -m hypotrail report --study DIR --out FILE, with --json, --examples-dir DIR and --read-sequence N (the flags are in the commands table of chapter 04). The code is src/hypotrail/report/: gather.py reads and verifies the records (gather_agent.py adds what a Chinook Study holds), render.py writes the page and its sections (render_agent.py writes the sections that differ for a Chinook Study, markup.py holds the escaping building blocks), command.py is the command. It imports neither Inspect nor scikit-learn nor NumPy (ADR 0001), and it calls no fit, no prediction, no model and no tool, so it works with the network cut. An Inspect log is never opened: the page links to it.

  1. The Study is read, whichever Track it is of. --out must not be inside the Study, nor a directory, and its folder must exist.
  2. Every artifact the page shows is read back against its digest: a changed byte is ARTIFACT_INTEGRITY (exit 3) and no page is written.
  3. If the page shows public_check Items, the Study's writer lock is taken (a second writer is STUDY_LOCKED, exit 6), --read-sequence, when given, is compared with the Study's write sequence (STUDY_CHANGED, exit 6, or WRITE_SEQUENCE_AHEAD, exit 2; nothing is written, no Exposure and no page), the Workload is found through the one resolver of chapter 04 and its Protocol is checked against the revision's (PROTOCOL_CHANGED, exit 3), the freeze record is written first if the revision has none, then one journal entry names the Attempts, Assessments and Comparisons the page shows of those Items (chapter 12). A Study whose Items are all dev records nothing, takes no lock and does not compare --read-sequence.
  4. For a Bike Study, the command reads the data profile, as profile does, and hands it to the page. The read takes no lock and writes nothing, and the report never fails because of it: when the read is refused or fails, the Data profile section holds one sentence with its code and no figure. A Chinook page has no such section.
  5. The page is written to a temporary file beside --out, fsynced and renamed onto it, and the folder of --out is fsynced after the rename: an existing file is replaced.

The page is rebuilt from the Study each time it is asked for; it is never stored as a record. Two reports of the same public_check Study record two Exposures.

For a protected ranking Study, hypotrail --evaluator report checks the Study under its lock and writes JSON. It contains the Partition, Write sequence and aggregate Assessment and Comparison records, including their IDs. It leaves per-Item values in the private Study and creates no Exposure. Ordinary callers of report on this Study receive RANKING_HELD_OUT_REFUSED.

# a page for a Study; --out is outside the Study
uv run python -m hypotrail report --study runs/bike --out runs/bike-report.html
uv run python -m hypotrail report --study runs/chinook --out runs/chinook-report.html

The sections

The nine sections of the specification, in its order, then the Exposure section. A Bike page also holds the Data profile section, after Protocol and Partitions; a Chinook page does not. Each has a stable id. The page's own headings, labels and sentences are in English; a string that comes from outside the code (a question, an ID, a declared field) is shown as given, HTML-escaped, in text and in attributes, and a web address in it is text, never a link.

Exposure is not one of the nine sections of the specification: the ticket asks for it, and it comes last, so that the nine keep their order. Data profile is not one of the nine either: D-153 on chadlis/hypotrail#75 adds it to the page of a Bike Study only, after Protocol and Partitions. A Bike page therefore holds eleven sections, Exposure being the eleventh, and a Chinook page ten, Exposure being the tenth.

Wherever a section lists the Assessments of the Study, it lists them in the order of the later Assessment (chapter 10).

The tool-using agent Track's page

A Chinook Study has the same page, sections and rules. Where Bike shows a table by month and the ten largest errors, Chinook shows, for each Assessment, a matrix with one row per Case and one column per Repeat. Each cell names its Case and Repeat and holds the lines of the table below, with one line per Criterion of the Assessment's Scorer: the table shows those of chinook_contract_v1, and a text_facts_v1 Assessment has its five in their place, as its counters table has. An Instrument failure (a Criterion unscored or errored, with its Reason) is written apart from a format failure of the system (a Criterion scored false, with its Reason): the first is never held against the evaluated system. A Wrapped answer is named as such and carries the Reason invalid_response_format. The trace line is a relative link to the Attempt's Inspect log with its SHA-256 (the log itself is never opened); for an Import of a JSON Lines file it links the import source, which holds the steps; an Episode with no trace says trace absent.

An agent Comparison is shown as recorded: its Control and Candidate Assessments, its comparability (with the code of an order warning, and of a Declared-deviation warning, COMPARISON_DEVIATION_DECLARED, beside the status, chapter 11) and the checks behind it, its coverage and coverage rates, its deltas and the definition of the delta (for this Criterion a positive delta means the Candidate is better), and, aggregated by Case first, the shares of each Case from the paired-deltas file. When the record withholds the main delta (CMP-05) the page shows only withheld, with the coverage rates beside it and no bounds; no interval is computed over Episodes. Its descriptive measures show a null as unknown. When the record holds settings, a table shows one row per key: the key, the value of each side as JSON text (null where a side declares none) and its state.

A Study that holds a scenario Attempt (Mode scripted_fixture) shows the banner at the top of the page, before the first section, whatever else the Study holds: "test simulation, no LLM evaluated" is the text of the banner, and it names the scenario Attempts it covers by their IDs. Every element the page writes for a scenario Attempt carries a data-attempt-id attribute equal to that ID, and its text names no LLM. Its statuses and counts are shown under the heading Self-check of the scripted scenarios, not an Assessment: a scenario Attempt is neither assessed nor compared. Its final answers are shown as text like every answer. The page states no milestone status: the live acceptance status is shown by the grid and the README, not by a report of one Study.

The interval row

The Comparison table of both Tracks has one row after "Delta", "Interval", read from the record's interval (chapters 7 and 11): the two bounds, in the page's number format, the level, the unit with its count ("over 182 Items", "over 100 Cases") and, for blocks, the variant and the length ("circular blocks of 7 days"). For a withheld delta the row says "withheld" alone, with no bound. When no interval was computed it says why in words: the Workload of the Study's revision declares no resampling, or the population lists fewer days than its Partition, or fewer than two units; for a Comparison written before the interval, it says that no interval was recorded. The row states no significance and does not say which Configuration is better.

What the numbers are

Every value is written into the HTML when the page is rendered. The values the records hold (Metrics, counters, deltas, coverage) are read as recorded. Two tables hold values the records do not: the table by month (the Items of the month and the mean of the Assessment's per-Item absolute errors, with the number scored) and the Reasons per Criterion (the per-Item states, counted). Both are computed from the recorded per-Item file when the page is rendered, never when it is opened. The ten largest errors are ranked by absolute error, the larger first and equal errors by Item ID; the difference column is predicted minus true.

An Assessment's card shows, beside its Metric, its single-feature check as recorded (chapter 05): the lag features that beat it, each with its Metric; checked: no declared lag feature beats this Assessment when the field lists none; not checked when the record has no such field. A Comparison is shown with its Control and Candidate Assessments, its comparability status (with the code of a single-feature warning, and of a Declared-deviation warning, COMPARISON_DEVIATION_DECLARED, beside it, chapter 07) and warnings, its coverage and its deltas as recorded. A positive delta means the Candidate is worse. A Comparison against an Import is shown as descriptive, with its warning. An Attempt that is running is shown as running, whether or not its writer is alive, and an interrupted one as interrupted.

What the page does not say

The page never attributes readiness, safety or independence to an output, a Configuration or a Study. The one sentence that names those words denies them; it is listed here so that the test over the page's own text can allow it by its exact text.

Sentence
This report does not state that any output, Configuration or Study is production-ready, safe or independent.

Limits

Logs are linked, not read

The page links to an Inspect log with its SHA-256 and shows no event of it (Inspect owns its viewer). A Study that holds a log still renders where Inspect is not installed.

A report is an Exposure

Showing public_check outputs is an Exposure even with no Assessment. The entry is written before the page, so a failure to write the page leaves the entry.

No licence text

The Study keeps the dataset, not the licence notice or its attribution addresses: the page names the notice file the Workload declared and shows no notice text.

No in-page links

The only links are relative links to Study artifacts, from the folder of --out, each with its SHA-256. Moving the page without the Study breaks them.
