A Study may use its public_check Partition, and it records every use. Before the first use in a Study revision, the revision holds a freeze record: the digests of its Protocol, of every Configuration the Workload declares, of the environment and of the code. Every Assessment or Comparison that touches public_check Items, native or imported, for either Track, is an Exposure and is appended to the Study's journal. What the first Exposure may have informed is marked check_informed. A Study with no journal entry says that it recorded no Exposure and that any earlier exposure is unknown; nothing here claims that public_check was never seen.

What the commands do

No new command exists. assess and compare do the work, in src/hypotrail/ml/assess.py, src/hypotrail/agentic/assess.py, src/hypotrail/core/comparison.py and src/hypotrail/core/agent_comparison.py; the freeze record, the journal and the marks are in src/hypotrail/core/exposure.py, a core module (ADR 0001). Both commands take an optional --examples-dir, read only when the Items are public_check ones, to digest the Workload as it is declared now (default: the repository's examples/).

  1. The usual checks run first (chapters 05, 07, 08 and 11). A refusal there writes nothing.
  2. For public_check Items, the Workload's Protocol is digested again and compared with the one the current revision froze. A difference is refused with PROTOCOL_CHANGED (exit 3) and nothing is written: a Protocol change is made with init --study DIR --new-revision (chapter 10).
  3. If the revision has no freeze record, it is written now, before anything is computed on public_check Items. It is never rewritten, and a revision gets its own at its own first use.
  4. One journal entry is appended, pointing to that freeze record, and only then are the Items scored or paired. The entry is published atomically under the writer lock and never rewritten. An Assessment lists its Attempt and its own ID; a Comparison lists the Attempts and the Assessments of both sides and its own ID.
  5. The Workload's current digests are read through a function the entry point passes in (the Track's freeze_basis), so the core imports no Track. A library call that records an Exposure without passing that function (a Comparison of public_check Items through core.comparison.compare with no live_basis) is refused with WORKLOAD_BASIS_REQUIRED (exit 2) and nothing is written. For a Chinook Study the database part of the Protocol digest is the digest of the live file when it is readable, so a replaced database is refused with PROTOCOL_CHANGED; when the file is absent or unreadable it is the digest of the Study's own copy, and import agent and assess still succeed.

An entry written for a Comparison that is then refused at its coverage check stays: the Items were read, and the journal is not rewritten. Its Comparison ID names no Comparison. run ml on public_check is not an Exposure: it produces predictions and scores nothing.

# an Attempt on public_check, then its Assessment: the first Exposure of the Study
uv run python -m hypotrail run ml --study runs/bike --config seasonal_7 --partition public_check --request-id ml-public-a
uv run python -m hypotrail assess --study runs/bike --observations OBSERVATION_SET_ID --scorer regression_mae_v1 --references REFERENCES_ID
# the freeze record, the journal and every check_informed mark
uv run python -m hypotrail status --study runs/bike --json

The freeze record

One file per revision, revisions/N/freeze.json, beside that revision's StudySpec. It holds the digest of the Protocol, of each Configuration the Workload declares (seasonal_7 and ridge_v1 for the Bike, plain and verify for Chinook), of the environment (Python and the dependency lock) and of the code (revision and dirty state). A Configuration's digest is the one of its declared content, as an Attempt records it in effective_config.configuration.declared; a Chinook Configuration's also covers the system text it resolves to, so a change to plain changes verify too.

check_informed

Two things are marked. A revision created after the Study's first Exposure is marked, and every later one too; each revision takes its own freeze record at its own first use of public_check; earlier revisions and their records stay readable and unchanged. A Configuration whose digest is not in the freeze record written before the Study's first Exposure, whatever the revision, marks every Attempt, Assessment and Comparison that uses it. A Configuration changed or added after that point is a new revision of the Configuration, identified by its new digest: it is not refused and needs no new Study revision, which is for Protocol changes only. A Configuration the freeze holds unchanged is not marked.

An Import has no Configuration digest, so it is never marked through a Configuration, and its producer's exposure to public_check stays unknown (saw_public_check, chapters 06 and 08). The marks are shown by status and, in a report, by #10.

Refusals

The refusals of chapters 05, 07, 08 and 11 apply as they are, except that ASSESSMENT_PUBLIC_CHECK_REFUSED and, inside a Study, PUBLIC_CHECK_COMPARISON_REFUSED are gone. A Comparison of a dev side and a public_check side is refused as two populations (COMPARISON_POPULATION_DIFFERS). STUDY_LOCKED (exit 6) and the integrity refusals are those of chapter 04. One code is new. With --json, the error has code, message, stage and details, and stdout holds one object.

Limits

Not a proof of non-exposure

No lock can prove that the user never read the public CSV elsewhere, and a new Study is not evidence that public_check was unseen. The journal records what this Study did.

No report, no live campaign

The report's Exposure section, its display of check_informed and the live campaign on public_check are issue #10. No path here calls a model.

A revision is not marked into its Assessments

An Assessment made under a check_informed revision is not itself marked unless a Configuration marks it. The revision's own mark is in status.

Exposure before the score

The entry is written before the Items are scored or paired, so a crash between the entry and the Assessment leaves an entry whose Assessment ID names no Assessment. The journal errs on the side of recording.
