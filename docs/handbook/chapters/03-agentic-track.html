The agentic Track asks a model Chinook questions and scores the answer it keeps. This chapter describes the part that exists: the chinook_contract_v1 Scorer, which turns one Episode's raw final answer and its Reference into two Criteria, exact_table and format_valid, and keeps failures of the instrument apart from failures of the evaluated system. The spike chapter covers the runs and the log projection.

Where the Scorer lives

The Scorer is src/hypotrail/core/chinook_contract.py. It needs the standard library and jsonschema only; the core never imports Inspect (ADR 0001). Rescoring a kept log (agentic/rescore.py) projects the log, then applies this Scorer to each Episode. It calls neither the model nor a tool and never opens the Chinook file: the frozen References are enough. The output of every Episode records the Scorer's name, chinook_contract_v1, and its version, and two rescorings of one log give the same verdicts.

The Scorer takes the raw final answer unchanged and keeps it unchanged in its output, whether or not it respects the schema.

The two Criteria

CriterionScored true whenScored false when
exact_tableStatus, reason_code, columns in order, rows in the requested order, types and unit all equal the Reference.Any of them differs, or the answer is malformed (then every component is false).
format_validThe raw answer is one JSON object, with no Markdown fence and no prose, valid against the Workload's table-answer/1 schema.Otherwise, with the Reason invalid_response_format: text that is not JSON, a fenced object, an object with prose around it, a missing or extra field, or needs_clarification with non-empty rows.

The comparison rules are the spike's: no string is converted to a number, a boolean is not an integer, NULL stays NULL, non-finite numbers are refused, and no number is picked out of prose. The numeric tolerance is read from the Reference (numeric_absolute_tolerance), not from the code: on E08 an answer within 0.005 of 283910.04 is correct and one beyond it is not, and every other number, whose Reference tolerance is 0, is compared exactly.

format_valid does not need the Reference, so a missing Reference leaves it scored. A crash is caught where the core applies the Scorer to one Episode (apply_scorer): that Episode's Criteria become errored, the exception's type goes into the structured field error_type (the message is never kept or read), the other Episodes are still scored, and the Episode's execution status stays produced. The log projection of the spike keeps telling an Inspect scorer crash from an execution failure through structured fields of the log, never through error text.

Choices and limits worth knowing

Malformed means not exact

A malformed answer, including a valid JSON object with an extra field, is scored false on exact_table as well; format_valid carries the Reason.

Failed and missing Episodes

Rescoring leaves the Criteria of a failed or missing Episode, and of a produced Episode without a final answer, unset (criteria: None). How they are scored waits on an owner decision.

The schema is an input

The Scorer is given the Workload's table-answer/1 schema; it does not read it from disk, so rescoring opens no Workload file.

Not built

evidence_link_valid and contract success, counts per Criterion, the Assessment contract and a closed Scorer registry, and an Inspect adapter (ADR 0001's parity test applies if one is built).
