run agent records a native Attempt of the tool-using agent Track in a Chinook Study, from the Inspect log of the Attempt, the way run ml records a Bike Attempt (chapter 04): the same request identity and replay, the same running-then-terminal manifest, the same atomic artifacts, the same writer lock, status and recover. The order of its checks is the one of the order paragraph of chapter 04, where run agent differs from run ml. It has two Modes. scripted_fixture runs the Workload's seven technical scenarios with Inspect's mock model and the real tools, and records the scenario Attempt: a test of the instrument, with a labelled self-check, that is neither assessed nor compared. llm_live runs one Configuration on one Partition (dev or public_check), optionally on some of its Cases, for one to three Repeats, against an explicit Anthropic model; it is opt-in, bounded and paid, and it is never part of the tests.

The command

--mode, not --profile, and --config, not --variant (chadlis/hypotrail#1). --config is required in both Modes: an Attempt runs exactly one Configuration, and the scenario scripts ignore its system text but the Attempt records it. A Study of the temporal regression Track is refused (UNSUPPORTED_CAPABILITY, exit 2). A flag that belongs to the other Mode is refused too, with the same code: there is no fallback.

The order

Nothing is run before the checks that precede it, and the first refusal ends the command. The order is the one of the decision on chadlis/hypotrail#74:

  1. The argument checks (exit 2). First, on the argument alone, before the Study or the Workload is read: --read-sequence when given must be a non-negative integer (INVALID_ARGUMENTS). Then the flag checks, against the Workload's declaration only: the flags of the other Mode, the Configuration, the Partition (dev or public_check), the Repeats (1 to 3), the model (anthropic/<model>), the cost limit and the price list (each requires the other; the price list must price the model), and the Cases (each a Case of the Partition, none repeated). They come before the key is read and before Inspect is imported. Together with the Repeats bound they make the bound of the Attempt: at most the Partition's Cases times three Repeats, that is 24 Episodes on dev. spike live keeps its own bound of two Episodes on dev.
  2. The writer lock (STUDY_LOCKED, exit 6): a second writer is refused at once. Then --retry-of must name an Attempt of the Study (RETRY_OF_UNKNOWN, exit 2).
  3. The request is identified (below). The same request_id with the same request returns the recorded Attempt here: no key, no Inspect, no provider call, no scan. With another request it is REQUEST_CONFLICT. The identity is taken before the data is verified, so a database changed on disk is a changed request (the file's digest differs), and a References set changed by a new Study revision is too.
  4. When --read-sequence is given, it is compared with the Study's write sequence, under the lock and straight after the identity (chapter 04): older, STUDY_CHANGED (exit 6); above, WRITE_SEQUENCE_AHEAD (exit 2). Nothing is written. A replay never reaches this step.
  5. The Workload's data is verified against its lock (DATA_INTEGRITY, exit 3), and every Study artifact read is read back against its digest (ARTIFACT_INTEGRITY, exit 3).
  6. For a new request, the Workload's Protocol must still be the Study's (PROTOCOL_CHANGED, exit 3).
  7. Inspect must be importable (INSPECT_UNAVAILABLE, exit 5), in either Mode; then, for llm_live, HYPOTRAIL_ANTHROPIC_API_KEY must be set and no variable that would override it (LIVE_UNAVAILABLE, exit 5). Nothing is sent without the key. scripted_fixture never reads the key.
  8. The manifest is written running, the Episodes are run, the artifacts are published atomically and the terminal manifest is written last.

An Attempt stopped between its running manifest and its terminal one keeps what it published and is never shown as completed. status shows it as recoverable and recover records it interrupted, with outcome_unknown: true for llm_live, since a vanished lock does not prove that the provider call was cancelled. Nothing is resubmitted. A recorded Attempt may hold failed Episodes (an error of the provider, a limit): it is completed, exit 0, and the failed Episode has a Reason and no invented answer.

Exit 0 is a recorded Attempt, whatever its Episodes' outcomes; 2 is an input the command refuses, 3 an integrity or Protocol refusal, 4 an infrastructure failure, 5 a capability that is not available, 6 a lock held or a request_id that names another request. Every error has code, message, stage and details, and none holds a secret.

The request identity

The elements are those of chapter 04, and the agent Track fills them all: the command (run agent), the Workload, the Configuration, the Partition, the Cases, the Mode, the model, the Repeats, the digests of the input files, and the code revision; an llm_live request with a cost limit adds the cost limit by its value (cost_limit_usd) and the price list by the sha256 of its bytes (price_list_sha256), which a request without them, and one recorded before they existed, reads as null. The Configuration is held as it is recorded, its id, its declared content and its resolved system text, so a changed plain changes the request of verify, which extends it, and a change to another Configuration of the Workload leaves a replay a replay. The Cases are the Partition's Cases in the file's order: --cases omitted and every Case listed (in any order) are one request. The model is the one requested. For scripted_fixture the Partition and the Cases are null, the Repeats are 1 and the model is mockllm/model. The input digests are in the table below; a request that changes only one element is refused with that element's name.

What an Attempt records

The manifest is an attempt/1 record with the operation execute, the Mode, an attempt_id that is a UUID, and the code_environment of run ml. An llm_live manifest also keeps, outside effective_config, the digest of each Case it evaluates (case_digests, chapter 04), which compare reads. Its effective_config holds the keys below. model is the requested model and served_model the one the provider reports in the Episodes' outputs (output.model, the source of served_models in run.json; it is not the name the Inspect eval was given, which Inspect fills from the requested model). Both are always recorded side by side, as given: model with its provider prefix (anthropic/claude-sonnet-5-5), served_model as the outputs report it, without one (claude-sonnet-5-5), and a provider prefix alone is not a difference. The output without --json shows both names on its first line, as recorded (model anthropic/claude-sonnet-5-5, served_model claude-sonnet-5-5), also for an Attempt recorded earlier, and computes no flag from them. Several reported models are joined by a comma and a space, and none reported is null. limits are the effective limits read back from the log (the turn, time and output-token limits, the per-query caps, a concurrency of 1, the cache off, no retry, the cost limit, null without one, and parallel_tool_calls false: one tool call per turn is requested from the provider), and limit_notes states beside them what Inspect cannot enforce: the number of tool calls. An llm_live Attempt made with --episode-cost-limit-usd and --price-list also holds, with its running manifest, the two elements of the request identity they add, cost_limit_usd and price_list_sha256; an Attempt made without them holds neither key, so the table below lists the keys every Attempt holds. effective_parameters holds the reasoning setting and the output cap as the log recorded them in the request, and null for what it does not show. check_informed marks an Attempt whose Configuration the freeze record does not hold, once the Study has had its first Exposure; an llm_live Attempt on public_check scores nothing and is not itself an Exposure.

The files of an Attempt

Inspect owns the agent loop and its log. The log is written outside the Study, into a folder that is removed at the end; it is scanned for the key, then read through Inspect's public log API (never parsed by hand, ADR 0001) and kept in the Attempt as a raw artifact. The Observation set (origin generated, the Attempt's Mode) is projected from it: one Observation per expected Episode, produced, failed with its Reason, or missing (missing_from_log), with the final answer and the trace. Each Repeat is its own Inspect epoch. Tokens and cost are null where the log gives none, never 0. The population is a {"episodes": [...]} document of the Attempt (the selected Cases times the Repeats, all of one Partition), read by assess and compare as they read an Import's. No Reference is passed to the model, and the Chinook file is hashed before and after the Attempt: a difference is DATABASE_CHANGED and the Attempt is failed.

run.json is the run record of chapter 03, with every field the log holds taken from the log. For an llm_live Attempt it is the record #62 defines (request_source is this_attempt, the database hashes are the Attempt's own); for a scenario Attempt it is the library's record, with the banner.

The key is never kept

The key is read from HYPOTRAIL_ANTHROPIC_API_KEY and nowhere else, and is given to the provider explicitly. For an llm_live Attempt, every file the Attempt writes, the running and the terminal manifests included, is scanned for the key before it is written. A hit before the running manifest (a request_id that is the key, say) writes nothing and leaves no Attempt, exit 4, and the error has no warnings, since no scan of the Study is made. A later hit leaves the file unwritten, ends the Attempt failed with the Reason SECRET_IN_OUTPUT and exits 4; no file of the Study holds the key. After the Attempt the whole Study folder is scanned (the compressed logs are searched through Inspect's log API): a hit in a file that is no part of this Attempt is a warning on stderr and in the warnings list of the --json object, naming the file, and changes no recorded Attempt; the exit stays 0. The scan is made whether or not the Attempt failed: after a failed Attempt the same warnings are on stderr and in error.details.warnings of the --json object, and the exit is the error's. A replay runs no scan.

The scenario Attempt

scripted_fixture runs every scenario of the Workload once (SCN-01 to SCN-07, SCN-07 never run, so missing), through the real tools and the same task, projection and Scorer code as a live Attempt, with the model mockllm/model. Its Observation set holds the seven scenario Episodes and no Episode of a Workload Case; its population is an artifact of the Attempt, not the Study's memberships, which hold no scenario. self_check.json keeps the status of each scenario and the counters of each Criterion against the scenario file's own references (7 expected, 6 attempted, 5 produced, each scenario moving a different combination, as chapter 03 sets out). It is a labelled self-check, not an Assessment: it carries the Mode and the banner "test simulation, no LLM evaluated", which is also in the Inspect log header, it is never of the kind assessment, and no Assessment ID names it. assess on its Observation set is refused with UNSUPPORTED_CAPABILITY (exit 2) as the first check once the Observation set is found, before any check of its content, so compare can never see a scenario Attempt. The report that renders the banner is not built yet.

Two native Attempts, compared

The tests record two llm_live Attempts with the same code path and Inspect's mock model in place of the provider (plain and verify, the same dev Cases, Repeats, tools and limits), assess them with chinook_contract_v1 and compare them: the Comparison is compatible, strict, with configuration as the declared factor and no warning, and the Assessment's verdicts are those rescore_log gives on the same kept log. assess and compare run with the model, the tools and the Chinook file patched to fail. Two such Attempts that differ in their Repeats or in their requested model are refused with the code of that check unless --factor declares it. The patch is the tests' own: no flag of the command reaches it, and no such log is kept as a trace or presented as an LLM's result.

The paid Attempt

One paid Attempt was made for this slice, on 2026-11-20, after the exact command had passed offline, into a fresh Study made by init --workload chinook: uv run python -m hypotrail run agent --study STUDY --mode llm_live --config plain --partition dev --cases D03 --cases D05 --repeats 1 --model anthropic/claude-sonnet-5-5 --request-id live-check-1 --json. The command exited 0 and recorded an Attempt of status completed with two Episodes, D03 and D05, both produced, no failed or missing Episode and no warning. The requested model is anthropic/claude-sonnet-5-5 and the served_model the outputs report is claude-sonnet-5-5. run.json records, per Episode, 373 output tokens and 10,299 total tokens for D03, and 385 output tokens and 10,472 total tokens for D05, in three model calls each; the total counts the cached input tokens. The cost is not observable: cost is null in both Episodes and total_cost is null in their model_usage, so no price is stated here. In both Episodes uses_tool_result is null with the Reason answer_unreadable, and the Chinook file has the same SHA-256 before and after. The Episodes are not scored against References here.

The folder of the Attempt is kept as it was recorded under docs/handbook/traces/run-agent-live-plain/: the manifest (attempt.json), the Observation set (observation_set.json), its observations (observations.jsonl), the population, the Workload declaration, run.json and the Inspect log under inspect/, with the command's own --json output, command-output.json (ok true, replayed false, warnings empty), which backs the exit and the absence of warnings stated above. No file of it holds the key: the files and the decoded log were searched for its value before they were committed. It is a dated observation of one Attempt and says nothing about main once the code changes; the traces of spike live are those of chapter 03. The 72-Episode Campaign on public_check, two Attempts (plain and verify) with their Assessments, their Comparison and the report of the Study, is kept whole in docs/handbook/traces/campaign-public-check/; chapter 16 gives its account.

Limits

Tool calls are not capped

Inspect has no limit on the number of tool calls; the manifest says so in limit_notes. The turn limit bounds them indirectly.

The Campaign ran once

The 72-Episode Campaign on public_check is two invocations of this command, run on 2026-11-21 and kept as they were recorded; its order of Configurations is not alternated (chapter 16).

One provider

Only anthropic/<model> is accepted, with the key sent to that provider alone. The model licence line of the specification does not apply to a remote provider, and no field records one.

A scan is not a proof

The scan finds the key as written, in a file or decoded from a log; it does not find the key in an altered form.
