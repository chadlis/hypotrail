import agent also adopts an Inspect log (a .eval file written by the pinned Inspect) as an Import Attempt of a Chinook Study. The log is read once, through Inspect's public log API, and projected into one Episode per expected Case and Repeat with the projection that rescore_log uses. The trace of each Episode is kept in the Study, so assess --scorer chinook_contract_v1 scores evidence_link_valid from it, and gives the same verdicts as rescore_log on the same log. Neither the import nor the Assessment calls a model, runs a tool or opens the Chinook file. This chapter extends chapter 08, which describes the Study, the population, the request and the Assessment; it only says what differs for a log.

The command and how a source is told apart

The command is the one of chapter 08, with the same flags: --source names a log instead of a JSON Lines file. The kind of the source is decided by its extension and by nothing else: .eval is an Inspect log, any other extension is JSON Lines. The work is in src/hypotrail/agentic/imports.py (the order of chapter 08, with the log read in step 4) and src/hypotrail/agentic/inspect_log.py, the one module of the import that imports Inspect; it is loaded only for a log. The population file is the same {"episodes": [...]}, checked against the Protocol, and it alone gives the expected Episodes: the log never supplies or widens it.

uv run python -m hypotrail import agent --study runs/chinook --source docs/handbook/traces/live-l12-plain/inspect/LOG.eval --population population.json --request-id import-log-a
uv run python -m hypotrail assess --study runs/chinook --observations OBSERVATION_SET_ID --scorer chinook_contract_v1 --references REFERENCES_ID

What an Episode becomes

The log is read with read_eval_log and nothing else: there is no hand-written parser (ADR 0001). Each expected (Case, Repeat) is looked up among the log's samples (Inspect's epoch is 1-based, a Repeat 0-based), and an Episode the log does not hold is missing with the Reason missing_from_log, as the projection decides; this differs from a JSONL import, where an absent Episode is refused. A sample that is not an expected Episode, or two samples for one Episode, are refused. The execution status and the Reason of an Episode are the projection's (produced; failed by an execution error, a limit or the output cap; missing), and assess gives them the Criteria that chapter 03 gives them: a turn or token limit is scored false, a time limit, the output cap or an error is unscored.

The answer is the text of the final message, kept as raw_answer and scored as it is. The trace is the projected steps of the Episode (model turns, tool calls, tool results, the final answer), kept as data in the normalized Observations; nothing in it is executed. An Episode with no step keeps no trace, so its evidence link is unscored with trace_missing, as for an answer without a trace in chapter 08.

What is recorded, and as what

The original log is copied into the Study under attempts/ATTEMPT_ID/source/ and referenced with its digest, like a JSONL file; the validation report keeps source_format: inspect_log, the number of samples read and the checks that passed. What the log header states is recorded as declared and never as verified, only from the fields below (nothing else of the header, such as the model arguments or a base URL, is copied into a record; the original copy is the file as it was). import_time is the time of the import and is kept apart from generation_time, which is the header's creation time. The Import's Mode stays external_unknown: the Mode a header states is only the declared file_mode. A log whose model is Inspect's mock model is never labelled llm_live: if its header claims that Mode, file_mode is unknown. A log of a real model is not labelled llm_live either: it is a declared model, nothing more.

Whether the producer saw public_check values, its historical protocol, its tool use and the origin of the file stay unknown: a log does not establish them, and no record says the Episodes were produced independently. They are listed in the Observation set's unknown_fields, with the log. fields the header leaves out (an older log has no Configuration). The producer fields are the ones of chapter 08, under effective_config.producer and the Observation set's provenance; the other header fields of the table below are kept under log in the same two places.

The Inspect requirement and the refusals of a log import

A log import needs Inspect, and only a log import does: with Inspect not importable, the import of a .eval source is refused with INSPECT_UNAVAILABLE and exit 5 (capability unavailable) before the Study's lock is taken and before anything is read or written, while a JSONL import, assess and every other command run as before. The installed Inspect must be the supported version (0.3.287, the one pyproject.toml pins), else the same refusal; a log whose header states another Inspect version, or none, is LOG_INSPECT_VERSION_UNSUPPORTED (exit 2, with the version it states and the supported one). A log the installed Inspect cannot read is LOG_NOT_READABLE, and only the type of Inspect's error is reported. The refusals of chapter 04 and the population refusals of chapter 08 apply to a log import too; the JSONL line refusals do not. Each refusal below publishes no Observation set.

An Assessment of public_check Episodes of a log is an Exposure like any other (chapter 12): it is journaled, and the log's producer's own exposure stays unknown.

Choices and limits worth knowing

One scoring path

An import keeps the answer and the steps, and assess scores them with the one Scorer function of core/chinook_contract.py, as it scores a JSONL answer. tests/test_import_log.py compares, for scripted logs and for each kept live log, every Criterion of every Episode with rescore_log's verdict.

The log is read once, then copied

The digest and the kept copy are taken from the file's bytes, and Inspect reads the file from its path: a file that changes during the import is not detected. The copy keeps whatever the log held, which is why only the listed header fields are recorded elsewhere.

Only .eval

Inspect can also write JSON logs; they are not recognised as a log source here, and are read as JSON Lines.

Not built

An Inspect @scorer adapter, a command that runs the agent into a Study.

The tests are tests/test_import_log.py (every criterion of the ticket), tests/test_study_lock.py (the second writer) and tests/test_handbook.py (the tables of this chapter against the code). They run offline, call no model and use logs written by Inspect's mock model and the kept live logs.
